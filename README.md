# Shadow Squad Discord Bot

Рабочий бот Discord-сервера гильдии Shadow Squad. Он синхронизирует роли с
составом World of Warcraft, ведёт посещаемость РТ и забирает данные из
Blizzard, WoW Audit и Warcraft Logs.

Проект настроен под один сервер:

- Discord-сервер: `Shadow Squad`;
- основной РТ: пятница и воскресенье, 21:00–00:00 МСК;
- голосовой канал РТ: `🎉"Спец" отряд`;
- объявления о сборе: `📯обьявления`;
- служебный канал: `🤖bot-console`.

## Что сейчас работает

### Роли и состав

- Новый участник получает роль «Гости» на 7 дней. Срок хранится в SQLite и не
  сбрасывается при перезапуске.
- Состав Blizzard проверяется в 08:00, 13:00 и 19:00 МСК.
- Если у игрока несколько персонажей, Discord-роль определяется по самому
  высокому рангу.
- Сержант с активной лекарской специализацией получает роль
  «Хила на крутилах».
- Исчезнувшие из состава роли снимаются через 48 часов. Очередь можно
  посмотреть через `/removal_queue`, а снять роли сразу — через
  `/remove_guild_roles`.
- Роль «Друзья» бот не меняет.
- Все изменения ролей записываются в историю. В служебный канал уходят только
  реальные добавления и снятия, без строк поиска и прочего отладочного шума.

Ранги Blizzard:

| Ранг | Discord-роль |
| ---: | --- |
| 0 | RL |
| 1 | Знаменосец |
| 2 | Сержант |
| 3 | Летописец |
| 4 | Рекрут |

### РТ и посещаемость

- Учёт начинается в 21:00 и заканчивается в 00:00 по пятницам и воскресеньям.
- Бот раз в минуту отмечает участников в голосовом канале РТ.
- 60% времени в канале засчитываются как присутствие.
- Вход после 21:15 считается опозданием.
- Резерв засчитывается как полное посещение.
- Предупреждённый пропуск не портит процент посещаемости.
- В 20:30 бот публикует объявление о сборе и отправляет офицерам список
  отсутствующих и опаздывающих.

В канале `🐷опоздуны` можно написать обычное сообщение об отсутствии.
Бот поставит `✅` и привяжет сообщение к ближайшему РТ. Если убрать реакцию
бота или удалить сообщение, предупреждение перестанет учитываться.

Для структурированного предупреждения есть `/absence`. При опоздании можно
указать примерное время прихода. Свою запись можно отменить через
`/absence_cancel`.

### Отчёты

- После РТ бот ищет публичный Warcraft Logs. В отчёт попадают участники,
  боссовые пулы, прогресс, лучшие результаты и первые две смерти каждого пула.
  Остальные смерти не учитываются: после команды на вайп они уже ничего не
  показывают.
- `/logs_report` публикует отчёт за выбранную дату и сравнивает его с
  предыдущим пятничным или воскресным РТ в той же зоне.
- `/logs_member` показывает статистику одного участника.
- `/logs_deaths` выводит общий рейтинг ранних смертей и расклад по каждому
  боссу от первого пула до последнего.
- WoW Audit используется для истории RCLootCouncil. Автоматический отчёт
  включает только предметы, выданные во время конкретного РТ.
- `/monthly_report` публикует месячную сводку посещаемости.

### Остальное

- `/event` создаёт быстрый сбор с кнопками «Участвую», «Резерв» и «Не иду».
- При входе в канал `Ключ` создаётся личная временная голосовая комната с
  ником владельца в названии.
- Через 24 часа после сообщения Frzok в канале тактик Сержанты получают
  напоминание.
- Ежедневная резервная копия SQLite создаётся в 04:30 МСК.
- Недельная развлекательная статистика сбрасывается по средам в 05:00 МСК.
- Выбор участника дня запускается ежедневно в 20:30 МСК.
- При перезапуске, повторных сбоях API и пропущенных задачах бот пишет Frzok в
  служебный канал.

## Установка

Нужен Python 3.10 или новее.

```powershell
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Минимальный набор настроек в `.env`:

- `DISCORD_BOT_TOKEN`;
- `BLIZZARD_CLIENT_ID` и `BLIZZARD_CLIENT_SECRET`;
- `BLIZZARD_REGION`, `BLIZZARD_REALM_SLUG` и `BLIZZARD_GUILD_SLUG`;
- `WOWAUDIT_API_KEY`;
- `WARCRAFTLOGS_CLIENT_ID` и `WARCRAFTLOGS_CLIENT_SECRET`;
- имя гильдии, сервер и регион Warcraft Logs.

Дополнительные параметры и примеры уже есть в `.env.example`.

Запуск:

```powershell
python bot.py
```

`bot_state.sqlite3` — рабочая база бота. Не удаляйте её при обновлении: там
лежат таймеры, привязки, посещаемость, история ролей и очередь отложенных
задач.

## Привязка персонажей

Сначала бот пробует взять имя персонажа из серверного ника, глобального имени
или Discord-логина. Например, из ника `Main | Иван` будет проверен персонаж
`Main`.

Если этого недостаточно, RL или Знаменосец добавляет явную привязку:

```text
/link member:@Участник characters:Main, Alt
```

Персонаж должен находиться в составе Blizzard. Один персонаж не может быть
привязан к нескольким Discord-участникам. Привязки хранятся в SQLite; стартовый
список при желании можно задать через `DISCORD_CHARACTER_LINKS`.

## Доступ к командам

Проверка прав выполняется и в Discord, и внутри обработчика команды.
Администратор сервера сохраняет аварийный доступ.

| Уровень | Роли | Команды |
| --- | --- | --- |
| Гость | Гости | `/roster` |
| Участник | Летописец, Рекрут, Друзья | `/roster`, `/pidors_of_the_week`, `/absence`, `/absence_cancel`, `/attendance`, `/attendance_member`, `/loot_history`, `/loot_member`, `/event` |
| Рейдер | Сержант | команды участника и `/pidor_of_the_day` |
| Офицер | Знаменосец, RL | команды рейдера, синхронизация, привязки, посещаемость, отчёты и аудит |
| Администратор | право Discord «Администратор» | все команды, включая восстановление базы |

Офицерские команды:

- роли и Blizzard: `/link`, `/links`, `/unlink`, `/sync`, `/sync_member`,
  `/sync_status`, `/role_audit`, `/role_history`, `/removal_queue`,
  `/remove_guild_roles`;
- посещаемость: `/attendance_start`, `/attendance_end`,
  `/attendance_current`, `/attendance_mark`, `/attendance_confirm`,
  `/absence_list`, `/monthly_report`;
- логи: `/logs_report`, `/logs_member`, `/logs_deaths`;
- объявления и состояние: `/heroic`, `/rt_start`, `/bot_status`.

Видимость команд настраивается один раз:

`Настройки сервера → Интеграции → Shadow Squad → Управление`.

Разрешения:

- команды участника — RL, Знаменосец, Сержант, Летописец, Рекрут и Друзья;
- `/pidor_of_the_day` — RL, Знаменосец и Сержант;
- офицерские команды — RL и Знаменосец;
- `/backup_status` и `/backup_restore` — администраторы;
- `/roster` — все роли.

Даже если команда по ошибке видна в меню, бот отклонит её вызов без нужной
роли.

## База и резервные копии

Копии лежат в каталоге `backups`, который исключён из Git. Срок хранения —
30 дней. Перед `/backup_restore` бот проверяет файл и отдельно сохраняет
текущее состояние базы. Для восстановления нужно ввести
`ВОССТАНОВИТЬ`.

На Linux используется служба из `deploy/shadow-squad-bot.service`. Рабочая
база сервера лежит вне каталога приложения:

```text
/var/lib/shadow-squad-bot/bot_state.sqlite3
```

После обновления стоит проверить:

```bash
systemctl is-active shadow-squad-bot
journalctl -u shadow-squad-bot -n 100 --no-pager
```

## Права Discord

В Developer Portal включите `Server Members Intent` и
`Message Content Intent`. Роли бота нужны следующие права:

- управление ролями;
- управление каналами;
- перемещение участников в голосовых каналах;
- отправка сообщений и добавление реакций;
- чтение истории сообщений;
- просмотр журнала аудита.

Роль бота должна находиться выше всех ролей, которыми он управляет.
